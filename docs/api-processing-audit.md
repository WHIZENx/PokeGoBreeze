# API processing audit

## What moved off the browser main thread

The API module owns the generator and the former `src/core/options` processors. It parses the upstream Game Master, asset trees, and PvPoke metadata, then emits independently cacheable JSON sections for options, CPM, PvP, global stat rankings, Pokemon, combats, assets, leagues, evolution chains, information, stickers, and trainers.

The web app hydrates its store exclusively from `REACT_APP_DATA_API_URL`. It no longer bundles or runs the Game Master, CPM, asset, or PvP metadata processors in the browser. If the processed API is unavailable, loading fails visibly instead of freezing the main thread with a local fallback.

## Operational notes

- Pokémon details and reusable Pokémon selectors now call `/api/v1/pokemon` once. The API fans out to PokeAPI for species, varieties, forms, and the evolution chain, adds cached Pokémon GO offensive/defensive move rankings for every form, deduplicates and normalizes the result, and caches both completed and in-flight requests. Candy color data also passes through `/api/v1/candy`; current Web data requests no longer call external JSON APIs directly.
- Image, animation, and sound URLs intentionally remain CDN URLs. They are browser assets rather than application data and proxying them would add API bandwidth and latency.
- The API repository is private, but its read-only HTTP endpoints are intentionally public because a browser cannot keep an API secret. CORS is an origin policy, not authentication.
- Add Vercel Firewall rate limits for abuse protection instead of embedding a token in the frontend.
- The scheduled workflow processes data every six hours and commits only changed output. Each changed push triggers Vercel through Git integration.
- Snapshot endpoints only read generated files. PvP ranking and team files pass through a cacheable API proxy; no Game Master processing runs during a request.
